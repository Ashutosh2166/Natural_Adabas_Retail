FILE 100: CUSTOMER-FILE
-----------------------
PURPOSE: Master customer records for all retail channels.
         Stores personal info, loyalty data, credit limits.

FIELDS:
 FIELD          TYPE    LEN  DESC/SUPER/SUB   DESCRIPTOR
 -------------- ------  ---  ---------------  ----------
 CUST-ID        N       8    PRIMARY KEY       DE (UNIQUE)
 FIRST-NAME     A       30
 LAST-NAME      A       30                     DE
 EMAIL          A       60                     DE (UNIQUE)
 PHONE          A       15
 ADDRESS-LINE1  A       60
 ADDRESS-LINE2  A       60
 CITY           A       30
 STATE          A       2                      DE
 ZIP            A       10
 COUNTRY        A       2
 CUST-TYPE      A       2    WH/CO/EM/RE       DE
 LOYALTY-TIER   A       1    B/S/G/P           DE
 LOYALTY-POINTS N       10
 TOTAL-SPEND    N(11.2)
 ORDER-COUNT    N       8
 CREDIT-LIMIT   N(9.2)
 STATUS         A       1    A/I/S/B           DE
 CREATED-DATE   D
 UPDATED-DATE   D
 LAST-ORDER-DATE D

NOTES:
- CUST-TYPE: WH=Wholesale, CO=Corporate, EM=Employee, RE=Retail
- LOYALTY-TIER: B=Bronze(<1000), S=Silver(1000-4999),
  G=Gold(5000-14999), P=Platinum(15000+)
- STATUS: A=Active, I=Inactive, S=Suspended, B=Blocked

PRIMARY ACCESS: BY CUST-ID (SEQUENTIAL AND RANDOM)
SECONDARY ACCESS: BY LAST-NAME, BY EMAIL, BY STATE, BY STATUS

------------------------
PURPOSE: Real-time inventory levels by product and location.
         Core transactional file - highest access frequency.

FIELDS:
 FIELD          TYPE    LEN  DESC/SUPER/SUB   DESCRIPTOR
 -------------- ------  ---  ---------------  ----------
 PROD-ID        N       8                      DE (COMPOUND)
 SKU            A       15                     DE
 LOCATION-ID    N       6                      DE (COMPOUND)
 LOCATION-TYPE  A       1    S/W               DE
 ON-HAND        N       8

 DAMAGED        N       8
 IN-TRANSIT     N       8
 SAFETY-STOCK   N       8
 REORDER-LEVEL  N       8
 REORDER-QTY    N       8
 LAST-COUNT-DATE D
 LAST-RECEIPT-DATE D
 STATUS         A       1    A/I/F              DE

NOTES:
- COMPOUND DESCRIPTOR: PROD-ID + LOCATION-ID (unique pair)
- AVAILABLE = ON-HAND - RESERVED - ALLOCATED - DAMAGED
- LOCATION-TYPE: S=Store, W=Warehouse
- STATUS: A=Active, I=Inactive, F=Frozen (no transactions)

CRITICAL FORMULA:
  AVAILABLE = ON-HAND - RESERVED - ALLOCATED - DAMAGED
  (MUST NEVER BE NEGATIVE IN CORRECT STATE)

13. STATUS CODE REFERENCE
===============================================================================

ORDER STATUS FLOW:
  NEW -> VAL -> RES -> CON -> PAD -> ALC -> SHP -> CMP
  Any -> CAN (cancellation)
  SHP/CMP -> RET (return initiated)

  NEW = New Order (not yet validated)
  VAL = Validated (customer, items, pricing verified)
  RES = Reserved (inventory reserved)
  CON = Confirmed (confirmation sent to customer)
  PAD = Paid (payment authorized/captured)
  ALC = Allocated (inventory allocated for fulfillment)
  SHP = Shipped (shipment created, in transit)
  CMP = Completed (delivered and confirmed)
  CAN = Cancelled
  RET = Return Initiated

RETURN STATUS FLOW:
  REQ -> APR -> RCV -> INS -> RST/DMG -> REF -> CLS
  REQ -> REJ (rejected)

  REQ = Requested
  APR = Approved
  REJ = Rejected
  RCV = Received (items received at warehouse/store)
  INS = Inspected
  RST = Restocked (returned to inventory)
  DMG = Damaged (sent to damaged inventory)
  REF = Refunded (payment refund processed)
  CLS = Closed

PO STATUS FLOW:
  DR -> SB -> AP -> SH -> PR/RC -> CL
  Any -> CA (cancelled)

  DR = Draft
  SB = Submitted
  AP = Approved
  SH = Shipped (by supplier)
  PR = Partial Receipt
  RC = Received (complete)
  CL = Closed
  CA = Cancelled

SHIPMENT STATUS FLOW:
  CR -> PK -> PD -> SH -> DL

  CR = Created
  PK = Picked
  PD = Packed
  SH = Shipped
  DL = Delivered

PAYMENT STATUS:
  AU = Authorized
  CP = Captured
  RF = Refunded (full)
  PR = Partial Refund
  RV = Reversed
  EX = Expired
  FL = Failed

INVENTORY TRANSFER STATUS:
  CR -> AP -> SH -> RC
  Any -> CA

14. ACCESS PATTERNS
===============================================================================

HIGH-FREQUENCY ACCESS (ONLINE/TRANSACTIONAL):
----------------------------------------------
1. INVENTORY CHECK: FIND INVENTORY BY PROD-ID + LOCATION-ID
   File 105, compound descriptor, ~50,000 reads/day
2. ORDER LOOKUP: FIND ORDER BY ORDER-ID or ORDER-NUMBER
   File 111, unique descriptor, ~30,000 reads/day
3. CUSTOMER LOOKUP: FIND CUSTOMER BY CUST-ID or EMAIL
   File 100, unique descriptor, ~20,000 reads/day
4. PRODUCT LOOKUP: FIND PRODUCT BY PROD-ID or SKU
   File 101, unique descriptor, ~40,000 reads/day
5. RESERVATION CREATE: STORE RESERVATION, UPDATE INVENTORY
   Files 106+105, ~10,000 writes/day

BATCH ACCESS (EOD PROCESSING):
-------------------------------
1. ORDER SCAN: READ ORDER BY ORDER-ID (full table scan)
   File 111, sequential, ~5,000,000 records
2. INVENTORY SCAN: READ INVENTORY BY PROD-ID (full scan)
   File 105, sequential, ~2,000,000 records
3. PAYMENT SCAN: FIND PAYMENT BY AUTH-DATE (date range)
   File 140, date descriptor, ~20,000 records/day
4. PROMOTION SCAN: READ PROMOTION BY PROMO-ID
   File 121, sequential, ~5,000 records

REPORT ACCESS:
--------------
1. SALES BY STORE/DATE: FIND ORDER BY DATE RANGE + STORE
   Files 111+112, compound search
2. INVENTORY STATUS: READ INVENTORY BY LOCATION
   File 105, sequential scan with location filter
3. SUPPLIER PERFORMANCE: FIND PO BY SUPPLIER + DATE RANGE
   Files 131+132, compound search
